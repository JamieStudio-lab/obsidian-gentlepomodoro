# CLAUDE.md

Project context for Claude Code sessions in this directory. Keep this file scannable in under 60 seconds.

## Project Summary

**Gentle Pomodoro** is an Obsidian plugin: a soothing, task-integrated Pomodoro timer that links sessions to Tasks-plugin markdown items and writes Dataview-compatible daily logs. Currently **v0.5.3 (beta)**.

**0.5.3 added:** the lofi player **remembers where it was** and reopens pre-seeked (user decision: **restore the position, never auto-play** — Obsidian startup must not burst into music, and iOS blocks first-play without an in-iframe tap anyway, which the hidden player has none of). Capture: `parsePlayerMessage` in [youtubeMusic.ts](youtubeMusic.ts) no longer throws away everything but `playerState` — `infoDelivery` now decodes to a new `{type:"info", state, currentTime, duration, videoId}` variant (every field nullable; the stream sends them piecemeal, never all at once), which is the ONLY way to read the clock (the postMessage protocol has no request/response getters — the JS API's getters just read a cache fed by this same stream). Storage: internal state fields `lastMusicVideoId`/`lastMusicPlaylistId`/`lastMusicSeconds` in [types.ts](types.ts) beside `lastGoalHitDate`, plus the user-facing `musicResume` toggle (default `true`, Music group in **both** settings-tab paths, desc shared via `MUSIC_RESUME_DESC`). The plugin owns persistence (`recordMusicPosition` / `clearMusicPosition` / `flushMusicPosition` / `musicResumeState` in [main.ts](main.ts)); the view owns the running picture. **Write amplification was the design constraint** — data.json lives in the vault, so every save is sync traffic: the ~4Hz stream only mutates in-memory fields (deduped to whole seconds, so ~1 update/sec, no disk), and the _save_ happens on boundaries — PAUSED, ⏹ Stop, ENDED, `destroyMusicIframe` (panel close / leaf move / URL change), `onunload` — with a dirty-flag-gated `MUSIC_POSITION_SAVE_MS` (60s, [constants.ts](constants.ts)) `registerInterval` as the force-quit backstop (worst case ≤60s of drift; a quiet beat is one boolean check). Restore: pure `resumeTarget(target, saved)` folds the offset into the parsed target and `buildEmbedUrl` emits it as `start=` — **read at iframe-build time only, deliberately NOT part of `lastMusicKey`** (keying on a value that moves every second would rebuild the iframe ~20×/sec — the iPhone-flicker regression family). `resumeTarget` returns its input _by reference_ when nothing applies, so `resumed !== target` is exactly "this embed carries a resume offset" (`musicResumeOffsetActive`). **Resume is keyed by video ID, not playlist index** (`index=` is 1-based while `infoDelivery.playlistIndex` is 0-based, and an index breaks when the playlist is reordered): inside a list the saved video wins over the one the URL names, so a playlist reopens on the item that was actually playing; the list context must match exactly, so a changed URL never inherits an offset. Guards, split by side: `isResumablePosition` (record side) drops the last `MUSIC_RESUME_END_MARGIN_SECONDS` (10s) of a track and anything with a non-positive `duration` — **which is how a live stream reports, so streams never store an offset**; `resumeTarget` (apply side) drops anything under `MUSIC_RESUME_MIN_SECONDS` (5s). The floor lives on the apply side _on purpose_: recording the opening seconds is what lets a restarted/looped track immediately overwrite a stale offset. **⏹ Stop = forget** (user's own framing — pause remembers, stop forgets; it doubles as the manual "start from the top" control with no new UI); ENDED clears too. Both also arm `musicSeekToZeroOnPlay`, a one-shot consumed on the next PLAYING transition that posts `seekTo(0, true)` (new in `PlayerCommandFunc`; args widened to accept booleans) — the loaded iframe still carries `start=N` in its URL, and YouTube is reported to re-apply it on every `loop=1` repeat, so without this a resumed mix would skip its own head forever. The seek is a no-op if the embed already restarted at 0, which makes the fix correct under either behavior — no device verification needed to be safe. New pure helpers are node-tested in [tests/youtubeMusic.test.ts](tests/youtubeMusic.test.ts) (67 cases in that file now), including corrupt-data.json defense and the playlist-advance case. No migration (the `Object.assign` merge covers the new fields), no new network surface, no README **Network use** change.

**0.5.2 fixed:** the **daily-goal notice fired spuriously on the first focus session of a new day** whenever the app crossed local midnight while open (laptop sleep included): `statusFocusBaseSeconds` in [main.ts](main.ts) cached today's logged focus total with **no date key** (unlike `LogManager`'s inner cache, which checks `focusTotalCacheDate`), and since the engine only ticks while running, the first emit of day 2 fed yesterday's total into `maybeFireGoalNotice` _before_ the async refetch corrected it — one short session fired the notice AND consumed `lastGoalHitDate`, silencing the legitimate goal hit later that day. **Not a timezone bug** (audited clean: every "today" is local `moment()` via `todayLocalStr()`, log files are named by session _start_ date, zero UTC usage). Fix: new pure `effectiveFocusBaseSeconds(baseSeconds, baseDate, today)` in [logManager.ts](logManager.ts) (a base stamped with a different local day counts as 0; tested in [tests/logManager.test.ts](tests/logManager.test.ts) incl. the day-2 repro), new `statusFocusBaseDate` field stamped from a `todayLocalStr()` resolved _before_ the await (a mid-fetch midnight can't mislabel the result — worst case the stale stamp triggers an immediate refetch next emit), `maybeRefreshFocusTotal` bypasses the 30s TTL whenever the stamp is stale, and all goal math funnels through `currentFocusSeconds()` (guarded base + live session; `focusGoalText` uses it, the old duplicate compute in `updateStatusBar` is gone). **Also decoupled goal bookkeeping from the status bar** (previously it lived in `updateStatusBar`, which early-returns when the bar is hidden — so "Show in status bar" off meant the notice never fired and the in-view meter's base never refreshed): a dedicated `goalTimerListener` registered in `onload` (torn down in `onunload`, mirroring `statusTimerListener`) runs the notice check + TTL-gated refetch on every engine emit; the refetch's landing pushes into open views directly via `refreshViewGoalProgress` (not just through the status bar), and `refreshViewGoalProgress` itself kicks the TTL-gated refetch so a freshly opened view self-heals while idle. **Also fixed the stale day-2 _display_ while fully idle** (second user report, same midnight family): every refresh trigger above is engine-emit-driven and the engine is silent while idle, so an app left open across midnight kept yesterday's "Today X / Y" (and its goal-met styling) painted until the day's first interaction — the math was already date-guarded, only the re-render trigger was missing. Fix: a `FOCUS_TOTAL_HEARTBEAT_MS` (60s, [constants.ts](constants.ts)) `registerInterval` in `onload` plus a window-`focus` kick (instant correction when a laptop wakes from overnight sleep) both run `maybeRefreshFocusTotal` while idle; quiet beats cost two compares (TTL + date stamp), a stale stamp refetches, and the landing force-renders the bar and pushes into open views (both pre-existing paths). Side benefit: manual edits to today's log note now surface within ~90s even while idle. **Also moved the goal notice to logged-totals-only** (user decision: don't interrupt mid-focus, and live time that never reaches the log — app quit/plugin disable mid-session — must not consume the once-per-day flag): `maybeFireGoalNotice` now runs ONLY from `maybeRefreshFocusTotal`'s landing (the sole place the logged total can newly cross; guarded by `today === todayLocalStr()` so a mid-fetch midnight can't fire day-2's notice off yesterday's file), fed the fresh file total with NO live seconds; `goalTimerListener` now just kicks the refetch. `writeLog` zeroes the plugin-level TTL via new `GentlePomoPlugin.invalidateFocusTotalCache()` (beside its existing inner-cache zero), so the notice lands with the end bell rather than ≤30s late (in-flight-fetch race worst case ~90s, self-heals). **Skipped focus sessions are forfeited** (user decision): `parseFocusTotalSeconds` excludes `Status:: cancelled` lines from the goal sum (meter AND notice — one function feeds both), so skipping the crossing session fires nothing and the meter visibly drops when the forfeited minutes leave it (accepted UX); Stop logs `finished` and still counts in full ("end early, keep the time" vs Skip's "discard"); only an explicit `cancelled` is excluded, so hand-edited lines without `Status::` still count (all test-locked). The status bar / in-view meter deliberately still count live in-progress seconds (display is reversible, the notice is not). No settings/schema changes.

**0.5.1 fixed:** the opt-in `🍅 N` per-task counter **broke Tasks-plugin date parsing** ([GitHub issue #2](https://github.com/JamieStudio-lab/obsidian-gentlepomodoro/issues/2)): `incrementPomodoroCount` in [taskLoader.ts](taskLoader.ts) appended the marker to the very **end of the line — after** the Tasks emoji fields (`⏳ 📅 🆔 …`), and the Tasks plugin only recognizes its fields when nothing but other fields follows them, so every field silently became plain description text (dates gone from Edit Task and date queries; the raw string looked fine). Fix: the marker is now inserted at the end of the task _description_ — **before the first Tasks metadata token** (new `TASKS_METADATA_TOKEN_REGEX`: dates ⏳📅🛫➕✅ plus ❌⛔🏁, priorities, 🔁, 🆔) — and an existing marker is **relocated on increment** (strip + re-insert, not in-place replace), so lines corrupted by ≤0.5.0 self-heal on the next finished focus session. A trailing block reference (`^block-id`, new `BLOCK_ID_REGEX`) stays at the very end; nested-task indentation is preserved. No settings/schema changes; tests extended in [tests/taskLoader.test.ts](tests/taskLoader.test.ts) (before-fields insert, multi-field, relocation, priority, block ref, indentation). **Also in 0.5.1 (user decision: keep the feature, warn + repair):** the placement logic is factored into `placePomodoroMarker`/`removePomodoroMarker`, shared with a new **repair path** — pure `repairPomodoroMarkerPlacement` (rewrites ONLY _harmful_ placements: marker after the first metadata token, or after a trailing `^block-id`; a mid-description `🍅 N` on a field-less line is deliberately left byte-for-byte untouched — false-positive guard, tested), `repairPomodoroMarkersInContent` (only `TASK_LINE_REGEX` lines, so daily-log `- 🍅 Focus |` lines and prose are never touched), and `repairPomodoroMarkersInVault` (tasksPath scope like the picker, `includes("🍅")` pre-filter, **only writes files that change**, via atomic `Vault.process`). The user-facing recovery flow is **four actions** (per user request): **Check** (`scanMisplacedPomodoroMarkersInVault` — pure dry run via the shared walker's `write: false`; Notice with counts + per-file breakdown via `logger.warn` so users can inspect an unexpectedly large number before acting), **Repair** (relocate, counts kept), **Remove** (`removeMisplacedPomodoroMarker` — deletes the misplaced marker; since the old bug only ever _appended_, this restores the exact pre-bug line; correctly-placed markers are NEVER deleted), and **Remove all** (`removeAnyPomodoroMarker` — the counter's full uninstall; deletes placed AND misplaced markers, gated by `MARKER_TAIL_REGEX`: only markers followed by nothing but Tasks fields, a block ref, or end-of-line — i.e. positions the plugin itself writes — so a user-typed mid-description `🍅 N` like "Buy 🍅 2 kg" is never deleted; tested). Exposed as `GentlePomoPlugin.checkPomodoroMarkers()` / `repairPomodoroMarkers()` / `removeMisplacedPomodoroMarkers()` / `removeAllPomodoroMarkers()` ([main.ts](main.ts), shared `runMarkerMaintenance` runner with one `repairInFlight` re-entry guard and result/failure `Notice`s), four commands (`check/repair/remove/remove-all-task-pomodoro-markers`), and four settings rows in the Task integration group in **both** settings-tab paths (declarative `SettingDefinitionAction` rows + imperative `addButton`; the imperative Remove buttons get red styling via `markDestructive` from [confirmModal.ts](confirmModal.ts)). **Repair/Remove confirm before writing:** both first run the read-only scan, bail with a notice if it finds nothing, and otherwise show a `confirmAction` dialog (new [confirmModal.ts](confirmModal.ts) — promise-based `Modal` subclass; resolves in `onClose` so Cancel/Esc/click-outside can never leave the promise dangling; the exported `markDestructive` helper probes for 1.13's `setDestructive()` at runtime and falls back to `setWarning()` on older Obsidian — both invoked through a structural probe type, NEVER as the typed members, because Obsidian review rejects any `@typescript-eslint/no-deprecated` disable) stating the exact line/file counts; the in-flight guard spans the dialog, so a second action can't start while one is open. The dialog is deliberately compact — one-line question body, and a `.gp-confirm-modal` width override in [styles.css](styles.css) (`max-width: min(24em, 90vw)`, scoped `body:not(.is-mobile)` so mobile keeps its native bottom-sheet sizing); the Task-integration setting descriptions are likewise kept to one or two short sentences (user preference — don't grow them back). The counter toggle's description now carries a **beta / edits-your-task-files warning**; both paths share module-level string consts (`POMO_COUNT_TOGGLE_DESC`, `REPAIR_MARKERS_NAME/DESC` in [GentlePomoSettingTab.ts](GentlePomoSettingTab.ts)) so they can't drift. `TimerEngine.maybeIncrementTaskPomodoroCount` switched from `vault.read`+`modify` to atomic `vault.process` (find-line logic now inside the sync callback).

**0.5.0 added:** **audio-only lofi music** via a hidden YouTube embed. User pastes a YouTube URL (video, `/live/` stream, or playlist) in the settings tab; the timer panel shows a ♪ play/pause/stop `.gp-controls-row` (new `gp-music-section` in [GentlePomoView.ts](GentlePomoView.ts) `onOpen`, between the task list and goal progress) — **no video is ever visible** (user decision; YouTube-ToS gray zone accepted). The iframe is a pure audio engine inside a visually-hidden host (`.gp-music-player`: 1×1, overflow hidden, opacity 0 — **hidden, not `display:none`**, to keep the media pipeline alive; a CSS class because inline styles are lint-banned; deliberately **no `clip-path`** — Obsidian review warns it's only partially supported by older installers). **No remote code:** the plugin NEVER loads `iframe_api` (the Obsidian-review red flag); it speaks the embed's postMessage wire protocol directly (the Vidstack/Media Extended approach) via the new pure module [youtubeMusic.ts](youtubeMusic.ts) — `parseYouTubeUrl` (watch/youtu.be//live//shorts//embed//v//playlist, m./music./nocookie hosts, scheme-less pastes, `t=`→`start=` via `parseStartTime`; rejects channel-`/live` links and non-11-char IDs), `buildEmbedUrl` (`youtube-nocookie.com/embed/…?enablejsapi=1&playsinline=1&rel=0&controls=0`, **no `origin=` param** — `app://obsidian.md` isn't a valid https origin), command/listening builders, `parsePlayerMessage` (onReady/onStateChange/infoDelivery/onError, throw-proof against foreign bus traffic), `musicVolumeTo100`. All pure + node-testable: [tests/youtubeMusic.test.ts](tests/youtubeMusic.test.ts). **Handshake:** iframe `load` → `MUSIC_LISTENING_DELAY_MS` (100ms, [constants.ts](constants.ts)) → post `{"event":"listening"}`, or the embed never streams events. **View wiring:** reconciliation lives in `applySettings()` (runs every 50ms tick + from the settings tab), hot path gated by a `lastMusicKey` = `"<toggle>|<loop>|<url>"` string guard (URL parsed only on change — do NOT parse per tick, that's the iPhone-flicker regression vector); `lastMusicEmbedUrl` gates iframe rebuilds; `destroyMusicIframe()` (also in `onClose`) removes the iframe — **removal is what stops playback**, implementing the "Show music player OFF = hide + stop" semantics with no engine involvement. A `window` `message` listener (registerDomEvent) checks `event.source === iframe.contentWindow` + `YT_ALLOWED_MESSAGE_ORIGINS` **before** parsing; onReady → `postMusicVolume()`, states swap the ♪ play/pause buttons (guarded by `musicPlayerState`), onError → one `Notice` per iframe build (`musicErrorNotified`; 101/150 = embedding disabled — needed because there's no visible player to show YouTube's error screen). **Settings:** `musicUrl`/`showMusicPlayer`/`musicVolume`/`musicLoop` in [types.ts](types.ts) + [constants.ts](constants.ts) (defaults `""`/`true`/`0.7`/`true` — 0.7 = segmented "Mid", round-trips exactly; no migration needed). **Loop:** baked into the embed URL by `buildEmbedUrl(target, loop)` — `loop=1` plus, for a single video without a list, `playlist=<its own id>` (YouTube's documented quirk: loop only works with a playlist param); flipping the toggle therefore rebuilds the iframe (stops playback — the setting desc says so). **Ended notice:** a _lasting_ ENDED state (finished video with loop off, or a live stream going offline) fires one Notice via `maybeNotifyMusicEnded` — armed on a playing→ENDED transition, disarmed if PLAYING/BUFFERING returns within `MUSIC_ENDED_NOTICE_DELAY_MS` (3s), because playlist auto-advance and loop restarts pass through ENDED and resume in ~a second; timeout cleared in `destroyMusicIframe()`. **Network-stall notices (inform-only, deliberately no auto-pause/reload):** a BUFFERING state lasting `MUSIC_STALL_NOTICE_DELAY_MS` (10s) fires a Notice via `maybeNotifyMusicStalled` — armed only on the _transition_ into BUFFERING (the ~4Hz infoDelivery repeats must not re-arm mid-episode after the timeout fires), disarmed on any other state, rate-limited to one per `MUSIC_STALL_RENOTIFY_MS` (5min) via `musicStallNotifiedAt` (flapping connections). A buffering player self-recovers when the network returns — pausing would break that (paused players need a manual tap + iOS autoplay gating), and auto-rebuilding the iframe can't resume without a user gesture on mobile; hence notices only. Also: ♪ play pressed before the handshake (`musicPlayerReady` false — e.g. vault opened offline) shows a "player hasn't loaded" Notice instead of posting a command the embed silently drops. New **Music** group (after Timer appearance) in **both** settings-tab paths ([GentlePomoSettingTab.ts](GentlePomoSettingTab.ts)); the declarative path uses the 1.13 `validate` hook (`validateMusicUrl` — empty string must validate clean, it runs on mount) which blocks bad URLs inline; the imperative fallback has no validation (bad URL just hides the section view-side). In-view settings panel: **Music volume** segmented row in the Audio section + reset-to-defaults coverage. **Music ducking (per GitHub feedback):** every sound cue dips playing music under it — `TimerEngine.playSound` calls `plugin.duckMusicInOpenViews(audioBuffer.duration)` (engine never touches the DOM; same forwarder pattern as `refreshViewGoalProgress`) → `view.duckMusic()`. The embed's `setVolume` has no native fade, so both ramps are **stepped** posts (`buildVolumeRamp` in [youtubeMusic.ts](youtubeMusic.ts), pure + tested — lands exactly on the target): down over `MUSIC_DUCK_DOWN_MS` (240ms) to `MUSIC_DUCK_FACTOR` (0.35) × user volume (multiplicative — "Low" never jumps louder), hold for the decoded clip's exact duration, back over `MUSIC_DUCK_UP_MS` (800ms), one post per `MUSIC_DUCK_STEP_MS` (60ms; all in [constants.ts](constants.ts)). `duckLevel` (last posted 0–1 volume, `null` = not ducking) is both the marker and the start of the next ramp, so a cue mid-duck extends the hold without double-dipping. `postMusicVolume()` now starts with `cancelMusicDuck()` — an explicit volume set (segmented control, reset, cross-view reconcile) always wins; `destroyMusicIframe()` cancels the timers; no-op unless the player is ready **and** playing/buffering. The tick reconciler needs no duck gate: ducking never touches `lastAppliedMusicVolume`, so it stays equal to the setting (no-op) until a real settings change fires it — which then cancels the duck by design. Also **replaced the war-drum and singing-bell recordings** (GitHub feedback: the old clips cut off abruptly); assets keep their filenames, so only the mp3 bytes + rebuilt `main.js` changed. **Known limits (documented, accepted):** iOS may refuse first-play without an in-iframe tap (none exists — player hidden) and pauses on background/screen-lock; commands sent before the handshake are dropped (no queue); moving the leaf rebuilds the view and stops playback. README gained a **Network use** section (required Obsidian disclosure): zero requests until a URL is set; embeds load from `youtube-nocookie.com`.

**0.4.4 added:** an **estimated end time** on the timer. While a session runs, `.gp-end-time` (new div in `.gp-timer-content`, built right after `.gp-mode-label` in [GentlePomoView.ts](GentlePomoView.ts) `onOpen`) shows the projected wall-clock finish, e.g. `Ends 15:30`. Unlike the deliberately-hidden countdown (`.gp-state-running .gp-timer-time { opacity: 0 }`), it stays **visible while running** — it's a static fact, not a ticking clock, so it fits the "gentle" no-countdown design. Computed **view-side** in `applySettings()` as `formatEndTime(Date.now() + state.remainingMs)` — this reconstructs the engine's private `targetTime` (sub-second jitter, invisible at minute precision), so there's **no `TimerEngine` change**. `formatEndTime` uses moment's locale-aware `LT` format and appends `(+1 day)` / `(+N days)` when the end lands on a later **calendar** day (`end.startOf("day").diff(moment().startOf("day"), "days")` — compared on local-midnight boundaries so it's DST-safe, not 24h chunks). Shown only when `showEndTime && isRunning && remainingMs > 0` (hidden on pause / stop / overtime); the DOM write is gated by a new `lastEndText` guard (mirrors `lastTimeText`), so it writes ~once/minute — no frosted-glass backdrop reflow. Handled inside `applySettings()` (which the tick listener already calls every tick) rather than the listener body, so the settings toggle live-updates open views via `applySettingsToOpenViews()`; `applySettings` now hoists its `state` lookup to the top and reuses it for both the end-time block and the day/night icon (one `const state`). New `showEndTime` boolean in `GentlePomoSettings` ([types.ts](types.ts)) + `DEFAULT_SETTINGS` ([constants.ts](constants.ts), `true` — existing users get it via the normal `Object.assign` merge, no migration). A **Show estimated end time** toggle was added to **both** the declarative `getSettingDefinitions()` and the imperative `display()` fallback in [GentlePomoSettingTab.ts](GentlePomoSettingTab.ts) (in the Timer appearance group, after Day/night indicator — keep both paths in sync). Required widening the moment stub in [momentTypes.ts](momentTypes.ts): factory input `string` → `string | number`, and `diff(other, unit?)` gains the optional `unit` — both additive (existing single-arg `diff` calls in [logManager.ts](logManager.ts) unaffected). New `.gp-end-time` CSS (right after `.gp-mode-label` in [styles.css](styles.css)) is white-with-shadow like the mode label so it reads on both the classic gradient and the frosted pane. The view toggles a **`.gp-visible`** class (not `.gp-hidden` — `display:none` can't animate), so the label **animates** in/out: a gentle fade + upward slide + `max-height` grow (~260ms), mirroring `.gp-total-time`'s recipe. Because `.gp-timer-visual` is a fixed square (`aspect-ratio: 1/1`), the reveal grows _inside_ it — only the mode label re-centers slightly, the controls below don't move. Reduced-motion users get an instant snap (`.gp-end-time` added to the `prefers-reduced-motion` `transition: none` / `transform: none` block). Also **reorganized the settings tab**: the timer-visual settings (**Theme**, **Day/night indicator**, **Show estimated end time**) are split out of "Display & behavior" into a new **Timer appearance** `.setHeading()` group, and the tab's section order is now **Display & behavior → Timer appearance → Long break → Daily focus goal → Task selector → Task integration** (task groups adjacent, timing groups adjacent; "Display & behavior" keeps logs folder / auto-open / status bar). Updated in both the declarative `getSettingDefinitions()` and imperative `display()` paths — **keep their section order in sync**.

## Architecture

State flows through a listener pattern:

```
GentlePomoPlugin (main.ts)
    │
    ├── TimerEngine ──emit(TimerState)──▶ GentlePomoView   (renders the visual timer)
    │                                  └▶ status bar in main.ts
    │
    ├── LogManager       (appends daily-log markdown lines, TTL cache for today's totals)
    └── GentlePomoSettingTab  (Obsidian PluginSettingTab)
```

- `TimerEngine` is the single source of truth for timer state. Every subscriber gets a fresh snapshot via `onChange`.
- The view does **not** own state — it reads from `TimerEngine` and dispatches user actions back to it.
- Persistence is Obsidian's `loadData()`/`saveData()`; defaults are merged from `DEFAULT_SETTINGS` in [constants.ts](constants.ts).

## Conventions

- **State updates flow through `TimerEngine.emit()`** → listeners. Never mutate `TimerState` from the View or status bar.
- **Defaults live in [constants.ts](constants.ts)** `DEFAULT_SETTINGS`. New settings must be added there and merged via `Object.assign` in `loadSettings()` ([main.ts](main.ts) `loadSettings`).
- **Task IDs** are detected via the `🆔` emoji marker. Log entries use Obsidian wiki-link syntax: `[[path|display name]]`.
- **CSS classes are `gp-*` prefixed.** Stay consistent — search [styles.css](styles.css) before inventing new names.
- **Logging:** use `logger.warn/error/debug` from [logger.ts](logger.ts), not raw `console.*`. The prefix `[GentlePomo]` is added automatically.
- **Audio assets** (`ding-sound.mp3`, `singing_bell_short.mp3`, `war-drum_short.mp3`) live at the project root and are loaded by relative path from [TimerEngine.ts](TimerEngine.ts).
- **Task parsing** must go through [taskLoader.ts](taskLoader.ts) (`loadTasks`, `groupTasksByDate`, `normalizeTaskText`, etc.) — never re-implement regex inline.

## Settings & Persistence

`GentlePomoSettings` in [types.ts](types.ts) is the schema. Stored by Obsidian in `data.json` at the project root. Modify via `plugin.settings.foo = ...` then `await plugin.saveSettings()`.

## Log Format

Daily file: `<folder>/YYYY-MM-DD-gentle-pomodoro-log.md`. One line per session, inline-field format so Dataview can query it:

```markdown
- 🍅 Focus | Task:: [[Projects/MyProject.md|Write Docs]] | ID:: abcd12 | Start:: 2025-12-23 10:00:00 | End:: 2025-12-23 10:25:00 | Scheduled:: 1500 | Pauses:: [] | Total:: 1500 | Status:: finished | Type:: focus
- ☕ Rest | Start:: 2025-12-23 10:25:00 | End:: 2025-12-23 10:30:00 | Scheduled:: 300 | Total:: 300 | Type:: short-break
- ☕ Rest | Start:: 2025-12-23 11:00:00 | End:: 2025-12-23 11:15:00 | Scheduled:: 900 | Total:: 900 | Type:: long-break
```

`Type::` was added in 0.1.0 — values are `focus | short-break | long-break`. Additive; existing Dataview queries still match.

Field order is **load-bearing** for users' Dataview queries — do not reorder or rename without a version bump and changelog note. The schema is locked in by [tests/logManager.test.ts](tests/logManager.test.ts).

## Important Quirks

- **`obsidian` dep is pinned to `^1.13.1`** (types-only npm package; 1.13 typings are required for the declarative settings API — `getSettingDefinitions()` in [GentlePomoSettingTab.ts](GentlePomoSettingTab.ts), with the imperative `display()` kept as the pre-1.13 fallback; keep both paths in sync when changing settings). [package.json](package.json) and [manifest.json](manifest.json) track 0.5.3; `minAppVersion` is **1.7.2** (raised from 1.0.0 for `Workspace.revealLeaf` / `Vault.createFolder`, which `eslint-plugin-obsidianmd`'s `no-unsupported-api` rule gates). [versions.json](versions.json) maps each plugin version to its `minAppVersion`.
- **Audio lifecycle:** [TimerEngine.ts](TimerEngine.ts) owns a single shared `AudioContext`, created lazily in `playSound()` and resumed if suspended; decoded clips are cached in `audioBuffers`. `TimerEngine.dispose()` (called from [main.ts](main.ts) `onunload`) closes the context and clears the tick loop — Chromium caps live `AudioContext`s, so it must not leak across disable/enable cycles.
- **`main.js` is the built artifact.** It's gitignored, but Obsidian loads it directly — you must `npm run build` (or have `npm run dev` running) before reloading the plugin.
- **iPad icon sizing needs a CSS `min-width` floor.** WebKit/Safari collapses an SVG flex item's main-axis (width) to ~min-content (~8px) while honoring height, so the control glyphs render as thin slivers — and a plain CSS `width` (even `!important`) does **not** fix it. The fix is a `min-width`/`min-height` floor (+ `flex-shrink: 0`) on `body.is-mobile/.is-tablet .gp-icon-btn svg.svg-icon` in [styles.css](styles.css); the `min-*` floor is the load-bearing part (the flex algorithm can't shrink below it), so don't drop it. It **must** be CSS, not inline `el.style.setProperty` — `eslint-plugin-obsidianmd`'s `no-static-styles-assignment` forbids inline style assignment (and disabling that rule). (Diagnosed device-side via Safari Web Inspector; desktop/iPhone were never affected.)
- **Auto-open** runs inside `this.app.workspace.onLayoutReady()`. A `MutationObserver` fallback waits for any settings/community-plugin modal to close before activating the view (handles freshly-installed-plugin UX).
- **`noImplicitOverride: true`** is enabled in [tsconfig.json](tsconfig.json). Always mark methods that override Obsidian base classes (`Plugin.onload`, `ItemView.onClose`, etc.) with `override`.
- **`package-lock.json` is tracked** — CI uses `npm ci` for reproducible builds (since 0.1.1). Regenerate with `npm install` whenever `package.json` changes.
- **Local-timezone date string** used for daily reset logic is `moment().format("YYYY-MM-DD")` (defined as `todayLocalStr()` in both [main.ts](main.ts) and [TimerEngine.ts](TimerEngine.ts)). Same format as the daily log file naming, so all "today" logic agrees.
- **Per-task counter is opt-in** (`incrementPomodoroCountOnFinish`, default off). When enabled, finishing a focus session linked to a task increments a lifetime `🍅 N` marker on the task line. The marker sits at the **end of the description, before the Tasks emoji fields** (since 0.5.1 — a trailing marker breaks Tasks date parsing, see issue #2) and before any trailing `^block-id`. Legacy `🍅 N (YYYY-MM-DD)` markers from an earlier 0.1.0 build are still readable; on the next increment the parens are stripped, the marker becomes `🍅 N+1`, and a misplaced (≤0.5.0 trailing) marker is relocated in front of the fields.
- **Internal state fields** in `GentlePomoSettings` (`lastGoalHitDate`, `sessionsSinceLongBreak`, `sessionCounterDate`) are persisted to `data.json` alongside user settings but are not surfaced in any settings UI — they implement the once-per-day notice and long-break counter.

## Don't Do This

- Don't add `setInterval` calls in the view — subscribe to `TimerEngine.onChange` instead.
- Don't touch the DOM from `TimerEngine` or `LogManager` — UI rendering belongs in the View.
- Don't reach into `this.app.metadataCache` for task parsing — use [taskLoader.ts](taskLoader.ts).
- Don't use `console.*` directly — go through [logger.ts](logger.ts) (and `console.log` is lint-blocked anyway).
- Don't reorder or rename inline fields in log lines — tests in [tests/logManager.test.ts](tests/logManager.test.ts) will fail, and users have Dataview queries pinned to the current schema.

## Reusable Patterns

- **Listener pattern:** `onChange/offChange/emit` in [TimerEngine.ts](TimerEngine.ts) — copy this shape for any new subscribable state.
- **Settings merge:** `Object.assign({}, DEFAULT_SETTINGS, loaded ?? {})` in [main.ts](main.ts) `loadSettings`.
- **TTL cache:** `FOCUS_TOTAL_CACHE_TTL_MS` + `lastFetchMs` + `fetchInFlight` pattern in [main.ts](main.ts) `maybeRefreshFocusTotal` and [logManager.ts](logManager.ts) `getTodayFocusSeconds` — reuse for any expensive periodic fetch.
